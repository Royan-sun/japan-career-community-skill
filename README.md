# Japan Information Design Admission Skill

一个面向计划申请日本「情報デザイン / デザイン学」相关大学院的中文用户的免费 AI Skill。

这个项目不是求职工具，而是把我自己的日本设计类大学院考学经验，与 AI 协作整理成可复用的考学流程、研究计划书思考框架、教授联系准备、作品集检查清单与面试准备方法，并在社群中免费分享、持续迭代。

## 为什么做这个项目

信息设计类考学的信息高度分散。很多申请者会同时遇到：

- 不清楚「情報デザイン」到底覆盖哪些研究方向；
- 不会根据自己的经历筛选学校、研究室与教授；
- 有作品或兴趣，但无法转化成明确的研究问题；
- 研究计划书容易写成“作品介绍”或“我想做某个东西”；
- 不知道联系教授前应该准备到什么程度；
- 作品集、研究计划书、面试之间缺乏统一逻辑；
- 网络经验很多，但不同学校、研究室要求差异很大。

因此，我尝试把个人经验从“零散建议”变成一个可以让其他人直接使用的 Skill。

## 项目流程

个人考学经验 → AI 协助拆解与结构化 → 生成 Skill / 模板 / Checklist → 在自建社群免费分享 → 收集真实提问与使用反馈 → 持续更新 → 对需要深度个性化支持的用户提供进一步服务。

免费 Skill 本身可以独立使用，不要求用户购买服务。

## AI 在项目中的作用

AI 主要用于：

1. 把零散经验整理为流程、判断条件和检查清单；
2. 将模糊的研究兴趣拆成“现象—问题—对象—方法—预期价值”；
3. 检查研究计划书、教授联系邮件、作品集说明之间是否逻辑一致；
4. 模拟教授追问，帮助申请者发现研究计划中的薄弱点；
5. 将社群中的高频问题沉淀为新的 Skill 模块。

人工负责：

- 提供真实考学经验与设计领域语境；
- 判断 AI 输出是否符合日本大学院申请逻辑；
- 删除没有依据的学校、教授、合格率等信息；
- 对募集要项、出愿条件、教授招生状态等信息要求用户以官方来源为准；
- 决定最终发布的知识内容与服务边界。

## 当前 MVP 模块

### 1. 方向定位
帮助用户把“我喜欢 UI / 服务设计 / 交互 / 情感体验”等兴趣进一步整理为可研究的问题。

### 2. 学校 / 研究室筛选思路
不是直接给学校排名，而是从研究主题匹配度、指导体制、作品与研究的关系、出愿条件、时间线等维度帮助用户建立筛选表。

### 3. 研究计划书结构化
围绕以下链路进行检查：

`背景 → 现象 / 问题 → 研究对象 → Research Question → 方法 → 预期结果 / 意义 → 为什么适合该研究室`

### 4. 教授联系准备
帮助用户判断联系教授前还缺哪些材料，并优化邮件结构；不会代替用户虚构研究经历或教授信息。

### 5. 作品集与研究计划一致性检查
检查作品集是否能证明用户的观察能力、设计过程、研究意识和方向连续性，而不只是展示视觉结果。

### 6. 面试模拟
根据研究计划书和作品集生成可能的追问，例如：

- 为什么这个问题值得研究？
- 为什么使用这个方法？
- 为什么选择这个研究室？
- 你的设计实践和研究之间是什么关系？
- 如果结果与假设不同怎么办？

## 使用示例

将 `SKILL.md` 作为 AI 的项目指令后，可以直接提出：

- “我本科是视觉传达，做过交互装置，现在想申请日本情报设计修士，但不知道研究方向怎么收窄。”
- “这是我的研究计划书草稿，请只检查研究逻辑，不要替我编文献和数据。”
- “我准备第一次联系教授，请先判断我的材料是否已经达到可以联系的程度。”
- “根据我的作品集和研究计划书，模拟一轮日本大学院面试追问。”

## 社群迭代

每次在社群分享后，记录：

- 用户在哪一步卡住；
- 哪些问题被反复提出；
- Skill 哪些回答过于泛化；
- 哪些模板最常被使用；
- 哪些需求需要进一步的一对一支持。

这些反馈会进入下一版 Skill。

## 项目原则

- 不承诺“保合格”；
- 不虚构学校、教授、招生名额、合格率或申请条件；
- 出愿信息、考试形式、语言要求、教授是否招生等必须以当年度官方募集要项或研究室页面为准；
- 不替申请者编造研究经历、作品过程或引用文献；
- 优先帮助用户建立自己的研究判断，而不是批量生成标准答案。
