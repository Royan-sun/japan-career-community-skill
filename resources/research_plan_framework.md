# 研究計画書：七段结构与逻辑检查

## 一、研究计划书到底在回答什么？

一份合格的研究计划书，本质上在回答审查老师的四个问题：

| 老师在想什么 | 对应部分 |
| --- | --- |
| 这个问题重要吗？ | 研究背景（はじめに） |
| 前人做到哪了、还缺什么？ | 課題設定・先行研究 |
| 你具体要做什么、怎么做？ | 研究目的・研究手法 |
| 做出来有什么用？ | 期待成果・意義 |

给设计背景学生的思维转换：

> 艺术作品更常回答“我想表达什么”；研究计划书要回答“这个领域还缺什么，我准备补什么”。

## 二、标准七段结构

1. 研究背景（はじめに）
2. 課題設定
3. 研究目的
4. 先行研究レビュー
5. 研究方法
6. 期待される成果・意義
7. 年次計画・参考文献

## 三、黄金逻辑链

`背景：〜という現状がある`

→ `課題：しかし〜は不十分である`

→ `目的：そこで本研究は〜を行う`

→ `先行研究：〜は示されているが、〜は未検討である`

→ `方法：具体的には〜`

每一段结尾都应该能自然接住下一段。如果需要“突然跳一步”才能理解，说明逻辑可能断了。

## 四、优先级

经验上优先看：

1. 与目标教授 / 研究室的匹配
2. 选题的新鲜感、创新度、当下性
3. 两年内是否能做完
4. 方法是否复杂

方法不是越高级越好，而是要能回答 Research Question。

## 五、研究范围控制

警惕以下题目：

- 一开始就要做完整 App / 平台
- 想一次解决宏大社会问题
- 同时研究太多人群 / 技术 / 场景
- 技术难度远超当前能力
- 两年内需要大量长期数据才能成立

优先把问题缩小到“可以被验证的一件事”。

### 例

过大：

> 开发一款 App 解决外国留学生在日本生活中的所有信息差。

更像研究的问题：

> 某种信息呈现方式是否能降低外国留学生完成特定行政手续时的理解错误？

## 六、先行研究不是论文摘要拼盘

先问：**我需要这篇文献证明什么？**

可承担的角色包括：

- 证明背景
- 证明某现象存在
- 说明已有方法
- 说明相似系统 / 设计
- 支撑研究对象选择
- 找到已有研究尚未处理的部分

不要为了制造“创新”而直接写“目前没人研究过”。研究缺口必须有证据。

## 七、研究方法匹配

方法由问题决定。

示例：

- 探索用户不知道为什么这样做 → 访谈 / 观察 / 质性分析
- 比较两个界面 → 任务实验、时间、错误率、可用性评价
- 研究情绪 / 感受差异 → SD 法、Likert、主观评价、访谈
- VR / AR / 互动系统 → 原型 + 用户实验 + 行为 / 主观 / 生理指标

AI 可辅助检索相似论文的方法，但最终要检查：

- 方法是否真的回答研究问题？
- 样本是否合理？
- 变量 / 指标是否明确？
- 两年内是否可执行？
