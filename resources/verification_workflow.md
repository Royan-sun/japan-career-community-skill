# 学校 / 教授 / 文献信息核验流程

本项目把“经验判断”和“当前事实”严格分开。

## 1. 必须按当年度重新核实的信息

- 出愿时间
- 募集要项
- 考试科目
- 是否有数学 / 专业笔试
- 日语 / 英语要求
- 作品集要求
- 研究计划书格式与字数
- 是否需要事前联系教授
- 招生人数
- 官方报录比
- 教授当年是否招生
- 研究室当前研究主题

旧攻略、社群经验、往年截图不能直接当成今年信息。

## 2. 学校筛选的信息源优先级

1. 学校 / 研究科当年度募集要项
2. 学校官方入试页面
3. 研究室 / 教授官方页面
4. Researchmap / KAKEN / CiNii / 学术数据库
5. 往届考生经验、社群分享

如果第 5 类信息和官方信息冲突，以当前官方信息为准。

## 3. 教授匹配三层验证

### Researchmap

重点看近两年：

- 论文
- 研究成果
- 共同作者
- 研究关键词

回答：**教授最近发表了什么？**

### KAKEN

重点看当前或近期科研费课题：

- 课题名称
- 研究期间
- 研究概要
- 成果

回答：**教授现在真正投入资源在研究什么？**

### 研究室官网

重点看：

- lab 当前主题
- 在做项目
- 学生成果 / 修士研究
- 新闻与活动

回答：**这个研究室实际上正在做什么？**

## 4. 文献检索流程

先把研究题目拆成“需要什么文献”，再搜索。

常用入口：

- Google / Google Scholar
- CiNii Research
- ACM Digital Library
- 目标教授近两年论文
- 相关国际会议，如 CHI、UIST、TEI、IUI、MM、SIGGRAPH 等

找到较新的核心论文后：

- 向后看 References：这个领域建立在什么研究上？
- 向前看 Citations：后来谁沿着它继续做？
- 看 Related work：常出现哪些关键词和作者？

每篇进入计划书的论文都要回答：**它在我的逻辑里负责证明什么？**

## 5. 给初学者解释研究方向时

不要只返回一串论文标题。

尽量用以下结构解释一个真实案例：

1. 现实里它长什么样？
2. 研究者真正问的问题是什么？
3. 做了什么系统 / demo / 实验？
4. 怎么评价？
5. 得到了什么发现？
6. 未来可能应用在哪里？

若论文作者、lab、ACM SIGCHI 等有官方 YouTube demo，可一起提供，帮助学生理解科研里的交互形式。
