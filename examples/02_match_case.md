# Example 02 — 研究方向匹配，但考试制度不适合怎么办？

> 以下为虚构示例，用于展示 Skill 的工作方式。

## 学生输入

- 国内设计专业大四
- 想研究 VR × 用户体验
- 日语可以交流，英语已有成绩
- 没有数学 / 算法基础
- 做过一个简单 Unity demo

## 错误推荐方式

> “某教授研究 VR，所以你应该报他的学校。”

这不够，因为研究匹配不等于入试适配。

## Skill 的 Match 流程

### 1. 先建立候选学校池

根据 VR / HCI / 交互方向寻找相关综合类大学。

### 2. 检查入试制度

对每所学校核实：

- 是否有数学笔试；
- 是否有专业课考试；
- 日语 / 英语要求；
- 是否要作品集；
- 研究计划书格式；
- 是否需要事前联系教授；
- 出愿与考试日期。

如果某研究科的核心筛选是高难度数学笔试，那么对当前学生来说，即使教授研究非常匹配，也可能不适合作为主申校。

### 3. 再匹配教授

对通过第一轮的学校，使用：

- Researchmap 近两年论文；
- KAKEN 当前 / 近期课题；
- 研究室官网；

判断教授在**研究主题**和**研究方法**上是否匹配。

### 4. 修正学校难度

继续检查：

- 报录比；
- 内部生倾向；
- 教授当年是否招生；
- 研究室名额与热门程度；
- 往届考试经验。

### 5. 形成组合

最终不是只留一所“最喜欢的学校”，而是形成：

- 冲刺
- 主申
- 相对稳妥

并避免考试日期严重冲突。

## 结论

本 Skill 的推荐原则不是“研究最像 = 最应该考”，而是：

> **研究方向匹配 + 入试现实可准备 + 教授当年可招生 + 难度梯度合理。**
